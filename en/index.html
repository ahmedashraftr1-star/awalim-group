    The stack·المنظومة التقنية

    Tools we know by heart

    We do not chase every new thing. Each tool here comes with the limit we hit in it — and knowing the limit is the difference between using a tool and mastering it.

    TypeScript Language

    Its types vanish at runtime. Anything crossing a system boundary is validated again with zod, not trusted because it type-checked.

    React Frontend

    It re-renders by default. Long lists need virtualisation, not more memo.

    Flutter Mobile

    It does not feel like iOS by default. Curves, overscroll and touch targets are decisions you make by hand, or the user feels the difference.

    Node · Express Backend

    Single-threaded: heavy computation stalls every request behind it. It belongs in a queue or a worker.

    PostgreSQL Database

    An index is skipped once you wrap its column in a function. And VACUUM is not a detail on a heavily-updated table.

    Drizzle ORM

    It does not hide SQL — which is why we chose it. What you cannot write in SQL you will not write here either.

    OpenAI · Claude Models

    It is wrong with total confidence. So it never holds a final decision: one tool, one permission, one output checked before anything is written.

    Playwright Testing

    It catches what the screen shows, not what the code claims. A flaky test is worse than no test: it teaches the team to ignore red.

    Firebase Cloud

    Fast to start, and its security rules are the whole application. They get written and tested, never left open "for now".

    Vercel Edge Delivery

    The edge is stateless: no long-lived database connection, no file on disk, no memory that survives two requests.

    Figma Design

    The design file is not the source of truth. The tokens in code are, or the two drift apart in silence.

    IFRS · IAS Standards

    The standard says what, not how. Isolation, rounding and exchange rates are decisions we make, document, and answer for.

    Before you get in touch

    If your question is not here, ask us on WhatsApp — we usually reply within working hours.

    Ask us on WhatsApp
    How long does an enterprise system take?

    It depends on scope. A full accounting system with its modules is built in increments over months, but a first usable version usually reaches you within a few weeks of the architecture being approved. We commit to a stated schedule in the scope document, and tell you immediately if anything changes.

    Do I own the code after handover?

    Yes, entirely. We hand over the repository, the documentation, the deployment accounts and the database. We keep no key that forces you to stay with us.

    Do you work with clients outside Palestine?

    Yes. We serve clients in more than ten countries; the work is fully remote with regular meetings and a shared tracking board.

    Does Smart Accountant replace the accountant?

    No. It replaces the repetitive manual work: entering invoices, posting routine entries, reconciling balances. The accounting judgement and the review stay human — and the system is designed to make that review easier, not to bypass it.

    How do you handle support after launch?

    Every delivery comes with an agreed care period for defects, and an optional maintenance contract afterwards. We never make your system's survival depend on that contract.

    Do you take over stalled projects from another team?

    Yes. We start with a blunt technical audit: what works, what must be rebuilt, and the cost of each path. Sometimes our recommendation is not to rebuild — and we say so.
